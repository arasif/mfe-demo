# mfe-demo: React Micro Frontend with Webpack Module Federation

A small learning project that shows how a React shell application loads a component from a separately built remote application at runtime. Both apps share one Redux store, React, and styles.

> **Purpose:** a hands-on prototype to understand micro frontend architecture. It is not a production system.

## What it demonstrates

- Splitting one web app into a **shell (host)** and a **remote** that are built and run separately
- Loading a remote component at runtime with **Webpack Module Federation** and `React.lazy`
- Sharing **React, react-dom, react-redux, and Redux Toolkit** as singletons, so both apps use one copy
- Sharing a **Redux store** across apps. The remote dispatches an action, and the shell's reducer handles it
- Sharing **CSS** through common class names and CSS variables
- Fixing **cross-origin** loading between two dev servers with CORS and CORP headers

## Architecture

```
Browser http://localhost:3000  (SHELL, host)
 ├── Header: "Cart items: N"            reads Redux store
 ├── Redux store (cart slice)           owned by shell
 └── <ProductList />  loaded at runtime
          │
          ▼  fetches manifest
Browser http://localhost:3001/remoteEntry.js  (PRODUCTS, remote)
 └── exposes "./ProductList" component
        └── "Add to cart" → dispatch({ type: "cart/addItem", payload })
```

## Prerequisites

- Node.js 18 or later (check with `node --version`)
- npm (installed with Node.js)
- VS Code (recommended) and Git

## Setup and run

Open two terminals in VS Code.

**Products (remote), terminal 1:**

```powershell
cd products
npm install
npm start
```

Wait for `compiled successfully`. Open http://localhost:3001/remoteEntry.js to confirm the manifest loads.

**Shell (host), terminal 2:**

```powershell
cd shell
npm install
npm start
```

Open **http://localhost:3000**. You should see a blue header showing "Cart items: 0" and a product list below it. Click **Add to cart**, and the header count increases.

Start the products app first, since the shell loads from it.

## How it works

1. The browser loads the shell at port 3000 and renders `App`.
2. `App` runs `React.lazy(() => import("products/ProductList"))`. This makes webpack fetch `http://localhost:3001/remoteEntry.js`.
3. The manifest tells the shell where the `ProductList` code is. The shell loads it.
4. Shared modules resolve to the shell's copies because they are singletons. The remote doesn't ship its own React or Redux.
5. Clicking **Add to cart** dispatches `{ type: "cart/addItem", payload: product }`.
6. The shell's `cart` slice handles the action and adds the product to `items`.
7. `useSelector` re-renders the header with the new count.

The two apps never import each other's source files. They agree only on the module names (`products`, `./ProductList`) and the action type string (`"cart/addItem"`).

## Key concepts

| Concept | Where it appears | Purpose |
|---|---|---|
| Module Federation | Both `webpack.config.js` files | Runtime sharing of modules between builds |
| `exposes` | `products/webpack.config.js` | Publishes a component to other apps |
| `remotes` | `shell/webpack.config.js` | Tells the shell where a remote lives |
| `remoteEntry.js` | Generated by webpack, served at port 3001 | Manifest describing the remote's modules |
| `singleton: true` | `shared` in both configs | Ensures only one copy of React and Redux exists |
| `React.lazy` + `Suspense` | `shell/src/App.jsx` | Loads the remote on demand and shows a fallback |
| `Provider` | `shell/src/bootstrap.jsx` | Makes the store available to all components |
| `createAction` / `extraReducers` | `ProductList.jsx` and `store.js` | Cross-app communication through Redux actions |

## Experiments

1. **Singleton check:** in `products/webpack.config.js`, set `react-redux` to `singleton: false` and remove the `react` entry. Reload. You'll see "could not find react-redux context value." Restore it afterward.
2. **Shell component in the remote:** expose a `Button` from the shell and import it in the products app as `shell/Button`.
3. **Third app:** copy `products` to `reviews` on port 3002, expose a component, add it to the shell's `remotes`, and render it with another `React.lazy`.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `Can't resolve './src/index.js'` | `src` folder is in the wrong place. It must sit directly inside the app folder, next to `public`. |
| `Loading script failed` in the shell | The products server isn't running. Start `npm start` in `products`. |
| `ERR_BLOCKED_BY_RESPONSE.NotSameOrigin` | The remote is missing the CORS and CORP headers in `devServer.headers`. |
| `could not find react-redux context value` | A shared dependency isn't marked as a singleton. |
| No `remoteEntry.js` in the folder | Expected. Webpack serves it from memory during `npm start`. Run `npx webpack --mode production` to create it in `dist/`. |

## Notes on the walkthrough

- Built step by step: create two apps, configure webpack and Module Federation, add React and Redux, then connect them with a shared store.
- The remote is built and deployed separately, so each team could release its app without rebuilding the shell. This demo runs both locally to show the mechanism.
- In a real project, shared code would usually live in a design-system package, and remotes would be deployed to their own hosting URLs.

## Limitations

- Uses development servers and hard-coded localhost URLs. A real deployment needs environment-based URLs and a production build.
- Demo data is hard-coded, and the cart doesn't persist after refresh.
- No authentication, error boundaries, or automated tests.
